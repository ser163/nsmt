# NSMT — Net Share Memory Tree（Yggdrasil）项目策划

> 版本：v0.1（草案）
> 作者：Harry（需求）/ Maka（架构建议）
> 日期：2026-08-30
> 状态：**待评审**

---

## 1. 项目概述

### 1.1 一句话

一个**多机器共享记忆 + 共享文件系统**的网络层：让家里电脑、公司电脑上的不同 agent（Maka / Hermes / 自定义）接入同一个"用户域"，共享同一棵记忆树和同一份共享文件，且能识别记忆归属、带锁协同编辑文件。

### 1.2 名称

| 项 | 值 |
|---|---|
| 项目名 | **Net Share Memory Tree** |
| 简称 | **NSMT / nsmt** |
| 正式代号 | **Yggdrasil**（北欧神话世界树，连接九界的巨树 —— 契合"记忆树 + 多机共享"） |
| 二进制名 | `ygg`（server）/ `yggd`（agent 客户端 daemon） |
| 备选代号 | Mnemosyne（希腊记忆女神，若偏好更直白的"记忆"主题） |

### 1.3 目标用户

- 个人多设备（家中 Mac / 公司电脑 / 云主机）上跑多个 agent 的用户；
- 希望 agent 之间共享记忆与文件、但又想保留机器/agent 边界的用户。

---

## 2. 需求拆解（来自 Harry）

1. **网络版记忆库**：多台机器共享一套记忆。
2. **快速网络协议**：优先低延迟、高效率。
3. **实现语言**：Rust 优先。
4. **机器身份**：每个 agent 运行后生成唯一机器码；标识结构 `<user_domain>/<machine_id>/<agent_tag>`（可优化，但保持三段式）。
5. **基于腾讯记忆架构扩展**：本地插件 + 远程服务器端。
6. **连接自动初始化**：连上服务器后自动同步机器表、agent 列表，所有客户端可知晓在线情况。
7. **共享文件系统**：
   - 所有客户端可访问、同步；
   - 在各客户端工作目录虚拟出**相同目录**；
   - 支持**文件链接**方式；
   - 注册协议时共享目录信息分发给每个客户端，用文件共享协议同步内容；
   - 可运行/共享/读取/修改；**修改需加锁防冲突**。
8. **共享记忆 + 共享文件**：不同机器上的 agent 都能访问用户域下的所有记忆；靠前缀/标识区分归属；还能共享记忆与文件。
9. **在腾讯记忆系统上加路由/隔离**。

## 3. 可行性评估

| 模块 | 可行性 | 依据/风险 |
|---|---|---|
| 身份与命名空间 | 🟢 高 | 机器码 = `IOPlatformUUID`/硬件标识 + hostname + OS 的稳定哈希 |
| QUIC 传输 | 🟢 高 | Rust `quinn` 成熟；低延迟多路复用 |
| 在线 registry/心跳 | 🟢 高 | 服务器注册表 + 定时心跳 + 广播 |
| 记忆隔离（instanceId） | 🟢 高 | 腾讯 Gateway 原生支持 `instanceId`，天然分区分机 |
| 记忆跨机查询路由 | 🟢 高 | NSMT 路由层把本机 `/recall` 转发到远端 Gateway |
| 共享文件系统（同步） | 🟡 中 | 内容寻址 + 增量同步（Syncthing 模式已验证） |
| 文件锁与冲突解决 | 🟡 中 | 租约锁（lease）+ 版本号 + 冲突副本；需精设计 |
| 大文件/断点续传 | 🟡 中 | chunk 级同步可做 |
| NAT 穿透 / P2P | 🔴 难（后期） | 第一版走 relay 服务器；P2P 打洞后续 |
| Rust 重写腾讯记忆 pipeline | 🔴 **不建议** | L0–L3 抽取是 Node/TS 数千行 + LLM 依赖；重写成本极高 |

**结论：整体可行。核心策略是"叠加而非重写"** —— Rust 负责网络/身份/文件/同步层，腾讯 Gateway 继续当记忆引擎，NSMT 通过 HTTP 桥接。

## 5. 身份与命名空间

### 5.1 全局限定名 FQN（Fully Qualified Name）

```
<user_domain> / <machine_id> / <agent_tag>
    ser163     /   9f2c81…  /   maka
```

- **user_domain**：用户域（如 GitHub 用户名 / 自定义域），是**鉴权与共享边界**；
- **machine_id**：机器码。生成规则：`SHA-256(IOPlatformUUID || hostname || os_version) → 前 12~16 hex`。稳定、不随重装应用而变（IOPlatformUUID 是硬件级）；
- **agent_tag**：该机器上的 agent 实例标识（`maka`、`hermes`、`custom`…），用户可配置。

### 5.2 密钥与身份

- 每台机器生成 **Ed25519 身份密钥对**（机器级），存 `~/.nsmt/identity.key`；
- 用户域级主密钥（`~/.nsmt/domain.key`）用于：签发给机器/agent 的凭证、可选加密；
- 首连服务器时用 **user_domain + domain 签名** 注册，服务器发 `machine ticket`（短期）。

### 5.3 记忆命名空间（映射到腾讯）

腾讯 Gateway 原生支持 `instanceId`（默认 `default`）。NSMT 约定：

| NSMT 概念 | 腾讯映射 | 说明 |
|---|---|---|
| machine | `instanceId = machine_id` | 同一 Gateway/DB 内天然分区分机 |
| agent | session_key 前缀 | `agent:main:<machine>/<agent_tag>/...` |
| 记忆归属 | FQN 前缀写入条目 | 查询结果带 `<machine>/<agent>` 来源标注 |
| 共享范围 | 条目 `scope: user/machine/agent` | user=全域共享，machine=本机，agent=仅本 agent |

**这就是"路由/隔离"**：隔离靠 instanceId 分区，路由靠 NSMT 层按 scope 转发。

## 6. 传输层设计

### 6.1 协议选型：QUIC (HTTP/3 over UDP)

理由：
- **快**：0-RTT 重连、UDP 低延迟、无 TCP 队头阻塞；
- **可靠**：内置重传/拥塞控制；
- **多路复用**：记忆查询 / 文件同步 / 心跳 / 在线广播 各自独立流，互不阻塞；
- Rust 生态：`quinn`（QUIC 实现）成熟，支持双向流、乱序。

备选：gRPC over HTTP/3（若偏好强类型 schema）、WebRTC DataChannel（P2P 场景）。

### 6.2 帧协议（自研轻量二进制帧）

```
+------+------+--------+--------+-------------+
| len  | type | flags  | stream | payload     |
| u32  | u8   | u8     | u32    | bytes       |
+------+------+--------+--------+-------------+
```
帧类型：`HELLO / REGISTER / HEARTBEAT / ONLINE_LIST / MEMORY_RECALL / MEMORY_CAPTURE / FILE_PUT / FILE_GET / FILE_DIFF / LOCK_ACQUIRE / LOCK_RELEASE / LOCK_NOTIFY / ERROR…`

### 6.3 拓扑

- **设计**：relay + P2P 同时设计（决策 #2）；协议按 P2P-ready 设计。
- **实现顺序**：v1 星型（relay）先行 —— 所有 yggd 连 ygg server，简单可靠；P2P mesh（服务器只做发现/信令、客户端 QUIC 直连）作为后续实现（协议已预留）。

### 6.4 在线状态

- yggd 每 10s 心跳；server 维护 `<FQN → (addr, last_seen)>`；
- 变化时 server 向所有在线客户端推送 `ONLINE_LIST` 增量（加入/离开）；
- 客户端本地维护 `machine 表 + agent 表`，供 UI/记忆路由使用。

## 7. 记忆层（扩展腾讯，不重写）

### 7.1 本地桥接

- yggd 启动时拉起/连接本机腾讯 Gateway（`:8420`，复用 `MEMORY_TENCENTDB_GATEWAY_CMD`）；
- 每机设 `instanceId = machine_id`，数据目录 `~/.memory-tencentdb/memory-tdai/` 可加机器后缀隔离（`vectors-<machine>.db` 或实例目录）；
- yggd 提供 HTTP 子代理：agent 记忆工具 → yggd → 本地 Gateway。

### 7.2 记忆读写模型：域池为主 + 本地托底（双写）

> 决策 #7（2026-08-30 修订）：域级公共记忆池为主存储，本地记忆库作托底。
> 一个记忆写两处；读时**先读网络（域池）**，**网络超时/失败才读托底**。

| 操作 | 行为 |
|---|---|
| `capture(...)` | **双写**：写入域级公共记忆池（主）+ 本地托底记忆库（备）。网络正常时两者都写；网络不可用时仅写本地并进**待同步队列**（恢复后补写池） |
| `recall(query, scope)` | **网络优先**：先查域级公共记忆池；网络超时/失败 → 回退读**本地托底记忆库**；结果统一标注来源 `pool/local` + `<machine>/<agent>` |
| scope=user | 双写（池 + 本地） |
| scope=machine/agent | 只写本地（不进池） |
| 识别归属 | 结果统一格式：`[<machine_id>/<agent_tag>] <content>`，并标注读取源 |
| 托底记忆库可配置 | 默认本机腾讯 Gateway；`MemoryBackend` trait 允许接入其它记忆库作托底 |

### 7.3 域级公共记忆池（主存储）

- 每租户在 server 上跑一个**域级腾讯 Gateway 实例**（独立 data dir `~/.nsmt/server/<user_domain>/`），作为该用户域的**权威共享记忆**；
- **双写**：scope=user 的记忆写入池（主）+ 本地（托底）；
- **读**：先池，网络超时/失败回退本地托底；
- 好处：任何机器在线即可取到全用户域记忆，不依赖"对方在线"；本地断网时读托底保底；
- 未启用域池的租户：退化为纯 relay（本地托底 + 在线各机转发）。

### 7.4 同步注意

- 记忆是"追加为主"，冲突少：向量条目按 `observed_at + hash` 幂等去重；
- 不跨机同步 sqlite 文件本身（避免向量库并发写坏），而是**通过 API 转发/聚合**。

## 8. 共享文件系统（重点难点）

### 8.1 目标形态

- 每台客户端工作目录下有一个**虚拟共享目录** `nsmt-share/`（可配置路径）；
- 目录内容在所有客户端**保持一致**（最终一致）；
- 通过**文件链接**方式装配：本地实体文件/缓存 + 目录树视图。

### 8.2 核心设计：内容寻址 + 目录树 + 按需拉取

```
nsmt-share/                         ← 每台机器相同的"视图"
├── docs/plan.md
├── assets/logo.png
└── code/agent.rs

本地实现（v1 实体同步 / v2 链接按需拉取）:
┌────────────────────────────┐
│ 目录树元数据 (tree hash)     │   ← 类似 Git 的 tree 对象
│  └─ path → (blob_id, mode)  │
├────────────────────────────┤
│ 对象库 (CAS, content-addr)  │   ← 文件按 chunk 哈希存储
│  .nsmt/objects/<sha256>     │
├────────────────────────────┤
│ 索引表 (idx)                │
│  └─ blob_id → (size, refs)  │
└────────────────────────────┘
```

- **文件链接方式（v1 采用，决策 #4）**：`nsmt-share/<path>` 是指向 `.nsmt/objects/<sha256>` 的 **symlink**（或硬链接）；按需拉取时先建 symlink 占位，后台流式补齐 chunk —— 这就是"虚拟出相同目录"的机制；v1 直接按此实现（不做实体同步过渡）。
- 目录树 hash 变化 → 增量同步（只传 diff 的 chunk）；
- 服务器存目录树 + 可选 CAS 仓库；客户端本地缓存，按需拉取。

### 8.3 同步协议

- `FILE_TREE`：推送最新树 hash；
- `FILE_DIFF`：比较两棵树，返回路径差异；
- `FILE_PUT/GET`：chunk 级上传/下载（QUIC 流，支持断点续传）；
- 变更事件：`watchdog` 监听本地目录 → 变更立即入队推送（QUIC 流，低延迟）。

### 8.4 锁机制（防修改冲突）

**服务器端租约锁（lease lock）**：

| 项 | 设计 |
|---|---|
| 锁粒度 | 文件级（路径） |
| 获取 | `LOCK_ACQUIRE {path, requester, ttl=30s}` → 服务器授予并广播 `LOCK_GRANTED` |
| 续约 | 客户端写期间每 10s `LOCK_RENEW`；过期自动释放 |
| 释放 | `LOCK_RELEASE`（写完成后）或租约到期 |
| 冲突策略 | 乐观并发兜底：文件带 `version`；写入时版本不匹配 → 保留冲突副本 `.sync-conflict-<machine>-<ts>` + `LOCK_NOTIFY` 通知相关客户端 |
| 强制锁(可选) | 目录写锁（需要整目录一致性时） |

### 8.5 权限（v1）

- 用户域内**全开放**：任何已注册的 machine/agent 可读、可运行、可共享、可写；
- 后续：文件级 ACL、agent 级黑/白名单。

### 8.6 服务端文件存储选型（分层）

| 阶段 | 元数据（树/索引/锁/注册表） | 文件内容（blob） |
|---|---|---|
| **v1 单机** | SQLite（`rusqlite`/`sqlx`）：目录树 hash、对象索引、锁、注册表 | **本地磁盘 CAS**：`objects/<user_domain>/<sha256>`；blob 层用 Rust `object_store` crate 抽象（原生 local） |
| **v2 扩容（已确认，决策 #10）** | 多机时元数据上 Postgres；**锁服务仍留在 ygg**（内存锁表 + SQLite 租约持久化，崩溃可恢复；多机升级 lease+DB） | **S3 兼容**（自建 MinIO / 腾讯 COS） |

- **决策 #10（2026-08-30）：对象存储后端选 S3 兼容（MinIO / 腾讯 COS）**。blob 层 `ObjectStore` trait 抽象 → **客户端协议不变**；v1 开发期可用 local backend（同抽象），**生产直接配置 MinIO 或腾讯 COS**；
- 大文件断点续传：chunk 级分片 + 每 chunk 独立上传（QUIC 流）；

## 9. 多租户（SaaS 化）

### 9.1 结论：天然支持

- FQN 顶层就是 `user_domain`，服务端所有资源都以 `user_domain` 为命名空间前缀 → **一台 `ygg` 服务可托管多个用户域（租户），互不可见**。
- 打包发布：一个 Rust 二进制 `ygg` 即多租户服务端；每个租户按需分配存储与记忆资源。

### 9.2 租户隔离模型

| 资源 | 隔离方式 |
|---|---|
| 身份/注册表 | `users/<user_domain>/machines…` |
| 在线状态 | 按 `user_domain` 分桶广播（用户只看得到自己的机器） |
| 记忆 | 每租户独立：本机记忆 + 可选**域级记忆池**（每租户一个腾讯 Gateway 实例、独立 data dir） |
| 文件 | CAS 对象库按 `objects/<user_domain>/<sha256>` 前缀隔离 + 每租户配额 |
| 锁 | `locks/<user_domain>/<path>`（路径本身在租户内，锁天然隔离） |
| 目录树 | `trees/<user_domain>/…` |

### 9.3 鉴权（多用户）

- **v1（起步）**：`username + 域密钥(Ed25519) + 邀请码` → 服务器签发短期 session token；机器用 token + 机器票注册。
- **v2**：邮箱密码 / OAuth（GitHub 等）。
- 每个请求都从**已认证 principal** 推导 `user_domain`，**服务端强制**只允许访问自己租户的命名空间（不信任客户端自报路径）。

### 9.4 记忆后端的多租户选项

| 方案 | 说明 | 适用 |
|---|---|---|
| **B. 域级记忆池（主存储，推荐）** | 租户启用池时，server 为其跑一个腾讯 Gateway 实例（独立 data dir `~/.nsmt/server/<user_domain>/`）作为**权威共享记忆**；本地 Gateway 作**托底**（双写 + 网络优先读） | SaaS/多机共享（**已确认，决策 #7**） |
| **A. 纯 relay（无池/托底模式）** | server 不存记忆；各机本地 Gateway 互为托底；未启用域池时退化为 relay 转发 | 自用、轻量、不启用域池的租户 |

> 决策 #7（2026-08-30 修订）：**A（域级公共记忆池为主）+ 本地托底记忆库**。
> 写双写（池+本地），读先池、网络超时读托底；托底可配置（`MemoryBackend` trait）。
> 域池未启用时退化为纯 relay。

资源随启用池的租户数线性增长：先按实例隔离，量大再优化为共享实例 + 前缀分区。

### 9.5 资源治理（防租户间干扰）

- 配额：每租户文件存储上限 + 带宽限速 + 并发连接上限；
- 限流：记忆/文件 API 按租户令牌桶；
- 管理：`ygg admin` CLI —— 建租户 / 发邀请码 / 查配额 / 吊销机器 / 看在线。

### 9.5.1 记忆池 worker 生命周期（防资源过载）

**原则：不给"每用户一个 Docker 容器"，而是"轻量 worker 池 + 按需拉起"。**

| 机制 | 说明 |
|---|---|
| 部署单元 | **Docker 只包整套服务**（一个 `ygg` 容器，内含 worker 监督器），容器级 cgroup 设总资源上限；**不是每租户一容器** |
| 记忆池 worker | 进程级监督：只有**活跃租户**才起 Node Gateway 子进程；**空闲 15–30min 自动回收**；首次 recall/capture **懒启动**（lazy spawn）；崩溃自动重启 + 熔断 |
| 每 worker 限额 | rlimit（RSS / CPU）+ 每租户并发上限；数据目录严格按 `~/.nsmt/server/<user_domain>/` 隔离 |
| 硬隔离升级路径 | 需要 SLA/安全硬隔离的租户 → 独立容器（按需付费），其余共享轻量模型 |

**效果**：大多数租户大多数时候 = **0 个 Node 进程**；Rust `ygg` 本体（registry/锁/路由，内存+SQLite）不随租户数显著膨胀。

### 9.6 安全

- 传输默认加密（QUIC = TLS 1.3）；可选端到端加密（用户数据仅客户端可见）；
- 租户隔离用**集成测试**保障（断言租户 A 无法访问租户 B 的任意命名空间）。

### 9.7 商业化接口（预留）

- 用量统计埋点（存储 / 带宽 / 记忆条数），后续可接计费。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| 文件锁在弱网/掉线下的死锁 | 租约 TTL + 强制回收；客户端崩溃自动释放 |
| 并发写冲突 | 版本号 + 冲突副本 + 通知（Syncthing 同款思路） |
| 向量库跨机并发写损坏 | **不直接同步 sqlite**，一律走 Gateway API / 转发 |
| NAT 穿透困难 | v1 走 relay；P2P 仅作可选增强 |
| 重写记忆引擎的诱惑 | **明确禁止**：只桥接，不重写；任何记忆能力缺失走腾讯官方 issue/PR |
| 代理/大陆网络 | 复用本机代理策略（QUIC 可走 UDP，relay 部署在国内可达位置） |
